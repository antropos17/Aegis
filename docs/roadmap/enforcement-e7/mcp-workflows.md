# Disposable MCP workflow qualification

Run `node scripts/qualification/qualify-mcp-workflows.mjs all` to execute 23 fixed
scenarios sequentially, or replace `all` with one scenario from the script's
`MODES` list. The command creates and removes its own temporary corpus and starts
only its fixed local HTTP receiver on literal `127.0.0.1`. It accepts no command,
endpoint, credential, account, recipient, project or output-path selector.

The collector uses the actual `createMcpGateway`, v4 route/credential binding,
current catalog/schema checks, known-secret guard and durable grant store. It
initializes the private credential key and computes its tag using the existing
route API. Each dummy grant names exact account, repository, recipient, operation
and payload arguments. Dummy tokens map to fixed accounts in the trusted receiver;
that mapping establishes no real provider account or repository identity.

The filesystem tool writes fixed dummy bytes to one generated file. The API tool
writes one local delivery byte instead of contacting an external API. The receiver
counts every tool delivery before interpreting its arguments. Forbidden scopes
produce a separate generated byte sentinel, so receiver-side refusal cannot mask
a gateway bypass. A separate report helper compares independently read bytes and
receiver counts with fixed expected results. Additional tests send actual traffic
around the gateway and corrupt observed bytes to prove these sentinels fail.

Scenarios cover positive filesystem/API effects; account, repository, recipient,
operation, payload and tool substitution; changed credentials, private key, route,
manifest and catalog; credential/route replacement after closing a prior session;
redirects; one-use replay and reconnect; cancellation before and after dispatch;
lost responses; and known-secret requests and schema-valid responses. After a
possible effect with a missing or refused response, the developer receipt records
`outcome-unknown`. A fresh gateway attempts the same consumed grant and produces
no second effect. The production JSON-RPC error protocol remains unchanged.

Each receiver stops at 96 requests, limits concurrent sockets to 16 with five-second
idle deadlines, bounds request bodies/headers to 8 KiB and bounds effect writes to
128 bytes. Existing gateway requests have finite deadlines; the
cancellation rendezvous is bounded to two seconds. `all` retains one scenario at
a time. Reports contain counters, fixed states and a dummy-byte digest, with no
credentials, payloads, upstream diagnostics or selected endpoints. Cleanup closes
gateway sessions and receiver sockets before removing the generated corpus.

Every receipt retains `developerOnly=true`, `launchAllowed=false`,
`realIdentityQualified=false` and `serverContainmentQualified=false`. This qualifies
the selected routed-call workflow with ordinary local fixtures. Arbitrary server
startup, native containment, real credentials, TLS-provider identity, network
enforcement, protected host/guest ownership and original-project writes remain
outside this command's evidence. Existing gateway behavior and production launch
authority are unchanged.
