# Local enforcement evidence qualification

This developer slice runs the existing action evaluator, v4 MCP HTTP gateway,
durable grant store and audit logger against generated local fixtures. It does
not execute the dummy Claude Bash label, native provider hooks or real requests.
Production launch remains unavailable; every receipt retains launchAllowed=false.

Run `node scripts/qualification/qualify-enforcement-evidence.mjs` without arguments.
Only the generated loopback receiver and fixed audit child are started. The
qualification imports no unmerged E4/E5/E7/E8 code. TEMP/TMP must select the task
fixture directory (TMPDIR on POSIX); parent and child both resolve os.tmpdir(),
so Linux does not require the Windows TEMP variable. Installed dependencies and
sidecars are reused.

## Owner events and correlation

createMcpGateway accepts an optional trusted onEvidence callback. It emits copied,
frozen events containing only schemaVersion=1, gateway-generated UUID operationId,
monotonic sequence and consumed/dispatch/completed/failed codes. RPC IDs, tool data,
URLs, credentials and upstream diagnostics do not enter these events. Consumed is
emitted only after consumeGatewayGrant resolves. Dispatch is emitted immediately
before peer.request, and reports entry into the owner invocation, not receiver
delivery. Completed follows accepted and secret-checked returned data. Failed
never asserts that an effect did not occur. No callback is enabled in production
callers by this slice.

Observer throws/rejections cannot change admission or results. getEvidenceStatus
reports emitted/lost/pending/sealed. finishEvidence closes event admission and
waits up to 250ms for pending asynchronous delivery, then accounts unresolved
callbacks as loss. Events are capped at 256 and loss at 65,535. Late rejection is
counted once; a later emit is loss. An owner finalizing while dispatch is in flight
must retain uncertainty, never treat a sealed snapshot as complete. A trusted
synchronous callback must itself return; hostile same-principal code is excluded.

encodeEnforcementEvidence serializes exact finite metadata. Imports are capped at
128KiB, 256 events and 64 receiver observations; strict JSON rejects invalid UTF-8,
duplicate decoded keys, unsupported schema and excess nesting. Context binds owner
session UUID, epoch, policy revision and declared source/corpus digests. These
digests label the selected local evidence, not hostile-loader executed-body
attestation. No low-entropy request/content hashes are published.

createEnforcementEvidenceAnchor is an explicit trusted creation boundary for the
owner of actual callback, terminal and independent receiver evidence. Its opaque
handle retains copied records and independently expected terminal count/digest.
Never create an anchor from imported claims. assessEnforcementEvidence compares
exact records/context/receiver evidence, rejects duplicate/reordered operations,
and distinguishes complete/incomplete/unknown telemetry from local links and
unknown external effects. A completed link requires the owner terminal record and
independently observed exact consumption/effect; replacing failed with completed
cannot mint a link. Imported complete/zero-loss fields carry no authority. A
valid audit prefix or new process with zero counters cannot repair missing history.

The disposable Ed25519 checkpoint fixture accepts an owner-selected opaque key
and exact expected anchor. It proves deterministic format and tamper/context/key
mismatch detection. It exports no private key and supplies no protected production
signing authority, completeness or launch authority.

## Executed fixtures

The policy's fixed never-executed dummy label maps to one exact v4 tool grant only
when the existing evaluator returns allow. Deny and unapproved ask create no grant.
The gateway retains credential/route/catalog checks and one-use replay refusal.
The independent receiver reads SHA-256(grant ID).used and exactly compares bounded
consumed bytes at delivery, then writes/readbacks its generated byte sentinel even
on absent/malformed/wrong-ID records. Receiver refusal cannot hide a bypass.
Lost response produces failed outcome evidence with one observed effect and no
retry; a consume collision dispatches zero times. Observer throw/reject/pending
cases preserve gateway results but expose incomplete delivery.

The actual audit logger runs only in a disposable child using generated userData
and loadSqlite:()=>null. logGatewayEvidence copies/freezes finite details before
buffering. The corpus uses log/flush/getDeliveryStatus/getStats/exportAll and
verifyChain. It executes small-buffer eviction, an exact-log append failure and
recovery, valid-prefix truncation, a fresh child with zero session drop counters,
and changed caller details before flush. The imported zero-loss metadata cannot
replace independently retained expected terminal evidence.

Fixtures cap HTTP request bytes at8KiB, response observation at4KiB, socket count16,
receiver effects2, audit child input/output128KiB and deadline10s. Cleanup walks
only its exact generated root, skips/refuses symlinks and caps depth3/64entries.
No original project, arbitrary command, real credentials/configuration or provider
is accessed. Independent root check receipts record source hashes and storage;
per-process heap limits do not bound all native or host memory.

VM protection, hostile storage, rollback/power-loss guarantees, original project
writes, real provider enforcement and A1-A4 remain unqualified. A hash chain,
signature, matching timestamp or imported success never supplies these authorities.
