# Native owned caller endpoint increment

This increment adds an internal endpoint owner and a local client connector at base `d495f116ca042e67d69ee7368fef2316c3a4a147`. `Program` does not call them. No dispatcher, privileged effect, enrollment, provisioning or production launch flag is added.

The owner duplicates the trusted launcher's retained peer handle, checks it against `CallerRegistration`, and derives logon SIDs from the actual retained peer token and current server token. The native descriptor has a protected, explicit DACL: server logon access `0x001f01ff`, and a distinct peer logon access `0x00100182`. The latter includes data write, attributes and synchronize, without `FILE_CREATE_PIPE_INSTANCE`. Same-logon server and peer rights merge into the server ACE. Consequently this local fixture establishes retained process admission, while dedicated protected principal installation and broker process protection remain required gates. A same-logon sibling can connect but cannot obtain the admission context.

The owner creates one noninheritable inbound message pipe with `FILE_FLAG_FIRST_PIPE_INSTANCE`, maximum instance count one, and `PIPE_REJECT_REMOTE_CLIENTS`. A random local locator identifies a transport; the independently retained server registration determines authority. The inspect frame contains neither locator nor PID, SID or executable path. The client checks the native server PID against its retained registration before returning the connected handle. Trusted registration/locator delivery across a protected installation remains unimplemented.

Connection polls use synchronous `PIPE_NOWAIT`, the Win32 nonblocking compatibility mode. This implementation does not use overlapped asynchronous I/O. Each native connect, read and write operation returns synchronously, leaving no pending overlapped allocation to drain. The owner accepts only `ERROR_PIPE_CONNECTED`, because a successful NOWAIT connect can merely mean that the pipe is listening. Connect budgets accept 1–2000 ms; the existing one-message admission has its separate 2000 ms read budget. Failed admission closes the endpoint, and the single consumed endpoint cannot reconnect. Disposal disconnects and closes without flushing. It may wait behind the serialized admission budgets. A returned context still uses the existing live registration, connected peer and two-second lease fences.

## Local native evidence

The maintained Windows x64 fixture compiles with inbox .NET Framework `csc`, `/target:exe /platform:x64 /optimize+ /warnaserror+`. Its successful peer is a separately launched child whose process handle the parent retains. The parent duplicates its own launch handle into that exact child with inheritance disabled; a fixture-only redirected stdin bootstrap delivers its handle value, locator and fixed inspect envelope fields. The child independently creates a server registration from that imported native handle and calls the production connector. This bootstrap supplies fixture transport setup and makes no production installation provenance claim.

Thirteen maintained controls cover that child positive, a same-logon unregistered sibling holding the valid locator/frame, a retained wrong-server registration, another instance and a pre-existing disposable pipe name, independent native descriptor and logon-token inspection, inspection of the distinct-peer ACE with an inert synthetic SID, a real changed-DACL-mask mutation, absent server/client deadlines, local rejection of a remote locator, idempotent disposal, and context invalidation after disposal. Native closure checks observe `ERROR_INVALID_HANDLE` on the original own pipe handle immediately after disposal; managed `IsClosed` alone is insufficient. The independent descriptor reader uses `GetSecurityInfo` and `TokenLogonSid`, rather than the endpoint's SID selection helper. The descriptor mutant compiles an altered native source into its own fixture and must fail the descriptor oracle. The occupied-name controls accept the actual ERROR_PIPE_BUSY (231) or ERROR_ACCESS_DENIED (5) refusal. With maximum instance count one, these tests do not isolate the first-instance flag from the instance-count limit; the flag itself is source-backed. The synthetic SID branch inspects a real disposable descriptor and its exact client mask, while providing no foreign-principal logon or access-check acceptance evidence.

These are actual Windows local process, token, pipe and descriptor observations. Remote-host rejection and foreign-principal admission are not exercised: the remote locator control is local policy validation, and the remote-reject creation flag is source-backed. No foreign account, global ACL or service is created. The original retained caller suite is checked alongside this increment; token policy changes owned by another worker require later composed verification. Full protected caller acceptance and production enforcement remain unqualified.

Diagnostics use the coordinator's bounded runner with per-process `TEMP/TMP` on X:, disabled Node compile cache and an 8 MiB log cap. Each test invocation leaves at most one small owned fixture directory containing two executables and one mutated source; final binaries and exact inputs are retained in the external review packet. Disposable prior diagnostic fixtures may be removed seven days after review, only within their recorded exact directories; this is a retention policy, not an automatic rotation claim. Normal user/system temporary directories are untouched.

[ConnectNamedPipe](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-connectnamedpipe) defines the NOWAIT listening/connected distinction. [Pipe wait modes](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-type-read-and-wait-modes) describes immediate nonblocking operation results and distinguishes compatibility mode from overlapped I/O.
