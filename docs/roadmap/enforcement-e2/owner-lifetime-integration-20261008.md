# Fixed guest owner-lifetime qualification phase

The phase in `scripts/qualification/cloud-guest-owner-lifetime.ps1` follows confirmed first-task, Claude, cancellation, and stdio native closures. Its expected SID comes from those checked native receipts. Guest bootstrap independently matches the existing `AegisTask` account and holds the manifest and trusted input streams while the admitted fixed runtime executes on the existing private desktop and outer Job. The helper creates a fresh nested Job for each case.

Both cases deliberately call `Environment.Exit(143)` on their own helper after readiness. The recovery case retains a trusted controller Job handle, observes the held members remain alive, explicitly terminates that Job, and confirms inventory closure and all held-member exits. The KOC case releases every witness Job handle before controlled owner exit and observes only pinned held-member exits. It records `jobClosureConfirmed = null` and `handle-released-not-observed`; no post-destruction Job census is inferred.

The native caller retains identity, admission and Job closure obligations. New task wait is 20 seconds, helper subprocess timeout 12 seconds and separate host phase timeout 60 seconds. Prior phase and admission budgets are unchanged. This phase starts no receiver. Result intake occurs only after the outer native zero exit and Job closure. The receipt reader reads at most 16 KiB plus one byte from one held stream before strict UTF-8 and exact two-line parsing. Bootstrap manifest intake similarly reads at most 64 KiB plus one byte from the stream retained through closure. UTF-8 BOM bytes count toward the limits; malformed UTF-8 fails.

The external R2 source packet received scoped independent Astra approval after its two stale-metadata read gaps were reproduced and corrected. The integrated checkout requires its own frozen review. Local tests execute actual Windows owner/helper/descendant lifetimes and nested admission, with separate synthetic ordering/shape controls. Repository reader fixtures are inert historical observation bytes and intentional unbounded negative fragments; they supply no current process, standard-user or guest observation. Test paths default beneath the caller's `TEMP` and can be set with `WorkRoot`; receipts and closed bounded artifacts stay outside repository sources.

`test-cloud-guest.ps1` includes the portable owner tests. They verify native cleanup refusals, closure-first result intake, actual inbox PowerShell 5.1 byte bounds, source guard/order/controller/transfer controls, maintained native composition caps and existing runtime controls. The paired baseline is the stored pre-integration source fixture, compiled with the same final optimized flags as the candidate. `test-cloud-guest-runtime.ps1` adds `/optimize+` while retaining its 80 KiB cap. The larger unoptimized candidate is an explicit negative size observation.

These local controls do not observe an actual standard-user guest private desktop, abrupt crash, host reboot or complete Windows VM matrix. They do not grant E2, E3, E6, acceptance, production launch or full E3.3 qualification. Those flags remain false until the required actual evidence and independent acceptance exist.
