# Inactive held-main operator binding contract

This increment composes the existing retained bootstrap Session with one exact held main registration. It implements an additional lifetime and operator-observation fence. Authenticated protected registration, allowed inventory/operations, installation, Program/main/preload activation and protected E1/A1 acceptance remain absent. An in-process trusted selection is not authenticated provisioning.

`CallerRegistration.RegisterMain` takes an already-held main process and the intended existing server registration. It duplicates and retains its own native process/token observations and a fresh registration generation. It retains the exact server object and shares that object's immutable gate. A registered main cannot become the source server for another main registration. Bound bootstrap preparation checks both the original server association and shared gate, so another server object cannot substitute even when it uses the same gate. No process is opened from a received PID, SID, session label or generation.

The main's routing Session label belongs to its server group. Its fresh Generation belongs to its own registration and is never equated with the server or broker generation. The operator comparison concerns the prepared broker child's native registration and main's native registration: observed user SID, authentication LUID and Windows session must match. The supervisor server may use a different principal. The tuple comparison is reused by existing token-context comparison; each native registration still requires its permitted primary token and rechecks complete token identity, groups, privileges, restrictions, integrity, TokenId and ModifiedId. Pipe impersonation type/level checks remain separate and unchanged.

`CallerBootstrap.PrepareForController` is opt-in. The old `Prepare` remains a server-fenced bootstrap primitive. The new Session retains the selected main object without consuming the external caller's main/server registration ownership. Initial setup, one-use Release, admission and issued Context checks revalidate it. Main exit, main revocation, server loss, operator change or an existing child/enrollment/endpoint fence failure terminally closes owned resources and reaches confirmed child/root/Job cleanup. A fresh same-process main registration cannot replace the retained revoked generation. Cancellation closes the owned child and transport while leaving borrowed live registrations owned by their caller.

The shared server/main/Session gate is acquired before existing inner enrollment/child/endpoint owners. Association is checked before touching an unrelated main registration. No arbitrary pair of separately owned gates is accepted and no inverse owner callback is introduced. Setup re-enters the same gate during export. Synchronous native admission/cleanup remain bounded by their existing observation budgets and may delay another request acquiring this gate.

An `ICallerSetup` interface, declared with the common Session unit, replaces the retained transport/check delegate pair and one-time configure closure. Supply remains after retained child/lease/endpoint construction and before the final owner check/publication. Early authority validation is inside PrepareCore's existing cleanup catch. The same first cleanup exception remains sticky, and every owned disposal attempt still runs. Existing standalone native compiler lists require no optional bootstrap implementation dependency. Compiler flags and the maintained 65,536-byte cap are unchanged; actual size is measured before acceptance.

Measured initial implementations exceeded that cap. The bounded reduction shares the identical guarded image digest between EnrollmentInspection and EnrollmentLease, removes redundant capturing cleanup callbacks while retaining sticky failures and every disposal attempt, and compares already unique ordinally sorted privilege snapshots by ordinal binary search. Restricting-SID lengths remain checked by the full entry comparison. SID_AND_ATTRIBUTES header/stride and TOKEN_GROUPS first-entry alignment use pointer-width arithmetic with all existing parser bounds retained. The fixture preserves the previous sequential structures independently, constructs a buffer using the runtime's marshaled layout and tests acceptance and short-table refusal on actual x64. These allocations are modeled buffers; x86 execution remains unqualified. Explicit null initialization is retained for the standalone partial compiler lists.

The meaningful baseline uses the preexisting API over real native objects: after admission, the independently held disposable main exits, the old issued Context still passes and the independent effect counter becomes one. This demonstrates the missing composition capability. The old API had no held-main contract. Corrected same-principal native controls require zero later effects after that exact main exits or its registration is revoked, positive same-operator admission, pre-release refusal, rejected server associations/reversed registration and confirmed owned cleanup.

Positive protected-descriptor checks use ENROLLMENT_LEASE_TEST; process/token/image/file/Job/pipe observations are real. The fixture's environment carries only disposable observation paths and the existing inheritance canary. The existing strict ordinary-root refusal must remain separately recorded from modeled descriptor acceptance. No actual different-user/logon/session provisioning or protected registration is tested here. The current primitive provides neither protected main-to-broker transport nor an operation dispatcher; existing check-to-later-effect and hostile privileged-race limits remain. Full E1.2/E1.4/E1.5 and VM/crash/reboot qualification stay incomplete.
