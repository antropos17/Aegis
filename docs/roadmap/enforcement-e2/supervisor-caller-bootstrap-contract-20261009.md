# Retained caller bootstrap input contract

This is an inactive internal composition of `CallerSession` and a single bootstrap input. `Program`, Electron main/preload, launch flags, authenticated operator registration, installation and provisioning remain outside this increment. Local native controls do not establish protected E1 or A1 acceptance.

`CallerBootstrap.Prepare` is a static opt-in factory returning the existing retained `CallerSession` owner. It prepares the fixed image through the existing pinned-image, suspended launcher, enrollment lease and exact-child endpoint. The controller supplies an already-held `CallerRegistration` for the intended endpoint server. It opens no process by PID, image name, environment variable or wire field. The returned Session retains the private transport until disposal and the supplied registration as a revocation fence without disposing another owner's registration. Its existing Context and sticky cleanup are reused.

The server registration's `Session` and `Generation` are registration-local labels. The frame carries the prepared child's endpoint session/generation, produced by that child's retained registration. The receiving child creates an independent expected-server registration from the imported native process handle. Its independently generated `Generation` is never equated with the parent's child-routing generation. `ConnectLocal` verifies the actual pipe server against the imported process's PID, birth, live primary token and retained handle.

## One input channel and one frame

The opt-in launcher creates an anonymous pipe with a 4096-byte buffer. Both parent handles initially exclude inheritance. Only the read handle becomes inheritable during this controlled launch. The extended startup attributes contain the existing atomic `JOB_LIST` plus an explicit `HANDLE_LIST` containing that read handle alone. `STARTF_USESTDHANDLES` names that read handle as stdin and sets stdout/stderr to `INVALID_HANDLE_VALUE`. No output channel, unrelated inheritable handle, Job handle, image handle or original server handle is on the allowlist. Ordinary `CallerLauncher.Prepare` and `Start` retain their previous no-inheritance startup path.

After suspended creation, the server registration duplicates its private held process into this exact held child with `PROCESS_QUERY_LIMITED_INFORMATION | SYNCHRONIZE` (`0x00101000`), inheritance disabled and no `DUPLICATE_SAME_ACCESS`. The child can query identity/token/liveness. The handle grants no process termination, memory write, remote-handle duplication or primary-token replacement right. The controller writes the frame and closes its writer before first release. The imported server handle is owned by the child's handle table; confirmed child/Job termination closes it on every setup/cancellation failure. Successful import duplicates the retained registration locally and closes the transferred handle.

The final encoding is exactly 144 ASCII bytes, without a terminator, length prefix or optional field:

| Offset | Width | Meaning |
| --- | --- | --- |
| 0 | 8 | Literal `AEGISB01` |
| 8 | 16 | Positive, aligned imported handle, lower-case hexadecimal |
| 24 | 8 | Observed server PID, lower-case hexadecimal |
| 32 | 16 | Positive observed server birth FILETIME, lower-case hexadecimal |
| 48 | 32 | Lower-case hexadecimal suffix of the owned local pipe locator |
| 80 | 32 | Prepared child's endpoint session label |
| 112 | 32 | Prepared child's endpoint generation label |

The PID/birth fields must match queries of the actual imported handle; they cannot nominate a process. The only accepted locator prefix is `\\.\pipe\aegis-owned-caller-`. All numeric fields have fixed width; zero/negative/unaligned handles, signed overflow, invalid or non-ASCII bytes, wrong magic, extra bytes and a second frame refuse. The design initially considered a 124-byte binary encoding. The final fixed ASCII encoding shares strict validation and reduces compiled code while retaining every held-handle/metadata/EOF check. The historical draft build and tests are retained separately.

`Receive` accepts only the actual stdin pipe, removes inheritance and checks the explicit stdout/stderr slots. `PeekNamedPipe` itself rejects a non-pipe or non-readable handle before `ReadFile`. One stopwatch covers all byte acquisition and the EOF wait, with a caller-selected total budget of 1–2000 ms. The controller completes one 144-byte write while the sole reader remains suspended. The receiver requires all 144 bytes to be available before its one native read; an observed partial frame or extra bytes refuse. It then requires observed broken-pipe EOF before parse, import, connection or payload. A complete frame with an open writer cannot proceed. An anonymous byte pipe records bytes, so this validation does not identify the history of multiple writes already buffered as one valid frame. Locator/session/generation alone supply no operator authority.

## Owner state and revocation

The bootstrap Session's immutable owner gate is the supplied server registration's gate. Ordinary Session preparation keeps its existing private gate. The lock order is this shared server/Session owner gate, then the existing inner lease/child/endpoint owners. None calls back into that gate. The one-time unpublished setup delegate supplies the fixed frame and re-enters the identical already-held server gate through `ExportBootstrap`; the monitor is reentrant. The retained transport-check delegate only checks transport flags and takes no owner locks. Existing standalone compiler units use only common `CallerRegistration`, `IDisposable` and `Action` field types and require no optional bootstrap source dependency.

Initial setup, Release, Accept and returned Context checks validate the server fence and transport state alongside the Session's enrollment/image/process/Job/token/endpoint fences. Failure terminally closes the Session, confirms owned child/root exit and queried Job emptiness, and closes the transport after child cleanup, including when an earlier cleanup fails. Cleanup uncertainty is retained and repeated by the Session's existing `caller-session-cleanup-unconfirmed` error. Disposal before release cancels the suspended child. Release is one-use; a duplicate refuses while preserving the already released child's retained owner, as in the existing launcher contract. Source server revocation invalidates later release/admission/context checks. Multiple bootstrap Sessions sharing one server registration serialize through that same gate, including bounded synchronous admission/cleanup.

The parent write is synchronous and bounded to 144 bytes into an empty private 4096-byte pipe while the sole child reader is suspended. The receiver uses synchronous native reads only after peeking available bytes. This does not provide arbitrary hostile-reader or privileged-handle-race cancellation guarantees. Cancellation/revocation occurs through the supervisor's owned child/Job termination, rather than a receiver `CancellationToken`. The inactive primitive has no background operation dispatcher. A check does not reserve an arbitrary later effect; final operation checks and protected controller delivery still require their own composition.

This is a missing composition capability demonstration. The old API did not promise bootstrap delivery. That historical JS harness used Vitest 4.1.11; final focused/neighbor suites use the unchanged lock's Vitest 5.0.3 in a fresh checkout.

Native positive controls observe initial suspension, no payload marker before release, one actual input, excluded inheritable file canary, actual reduced process access mask, denied termination access, verified server connection, exact-child admission and owner/context revocation. A deterministic fixture observation control holds a native writer with `FileShare.None`, signals the parent's read attempt and then closes it; the parent retries only native sharing/lock errors 32/33 under a finite observation budget. Those fixture observation handles are retained separately until the independent stopped-root and empty-Job checks finish. Negative controls exercise malformed/truncated/extra input, no frame, no EOF, invalid/overflow/substituted handles, mismatched real PID/birth, wrong held server, substituted canonical session/generation, cancellation, first-release refusal, duplicate release and setup failure. Fixture mutations temporarily duplicate the inherited read handle while the child is suspended, drain/rewrite the real pipe and close that duplicate before execution. Deadline controls retain only a writer, so the production receiver is the sole reader.

The fixture's environment values select disposable observation files and an independent canary. They provide no bootstrap identity or routing to production code. Only protected-descriptor acceptance is modeled through `ENROLLMENT_LEASE_TEST`; native image/file/process/Job/token/pipe objects and observations are real. Existing adjacent strict-root refusal controls cover the actual enrollment path, and the maintained production helper compiles without the test seam. A substituted canonical session/generation can let the child submit its inspect frame and marker before server admission refuses; no admitted context or operation follows. This is distinct from malformed bootstrap or wrong server metadata, which refuse before that marker. No protected-principal/operator/provenance acceptance is claimed.
