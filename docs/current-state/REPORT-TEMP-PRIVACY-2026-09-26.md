# Temporary HTML report privacy

AEGIS writes session and threat HTML reports into the exact `aegis-private-reports-v1` directory under Electron's temp path. Each filename contains 128 random bits and creation is exclusive. A report is capped at 8 MiB. POSIX creation uses directory mode `0700` and file mode `0600`, and refuses an existing directory owned by another user or accessible to group/other. Windows uses inherited ACLs; this change does not claim private Windows ACLs. File permissions and random names do not isolate reports from another process running under the same account on any OS.

The main process sweeps during startup initialization and every six hours while it runs. Each synchronous sweep checks at most 512 entries and removes at most 128 files, so a flooded directory cannot keep the Electron main thread in an unbounded scan. A capped sweep logs a generic retention warning. It considers only regular files with exact AEGIS report names in that directory; a matching name is a cleanup heuristic, not proof of who created a file. Reports younger than 24 hours remain available for the external viewer. Older reports expire at seven days; if known report bytes exceed 64 MiB, the oldest reports past the 24-hour grace are removed first. Changed and linked files are skipped; an unlink blocked by a sharing violation is retried later. The 64 MiB limit is a soft target while recent or undeletable reports remain, and a flooded directory may need manual review. Cleanup does not traverse the system temp directory or other applications' files. A 24-hour grace period does not establish that a viewer has closed a report.

Directory checks and later path-based writes or cleanup cannot be atomic with Node's cross-platform filesystem APIs. A process under the same account that replaces the report directory between those operations could redirect them. The checks reject an already linked directory; they are not a boundary against a racing same-account process.

Earlier AEGIS versions wrote timestamp-named reports directly in the shared temp root. Those historical files remain for manual review; this cleanup cannot establish their ownership safely.

Threat report IPC accepts only the current top-level AEGIS renderer, bounds text and list fields, and returns a generic error when opening fails. The threat HTML has a restrictive CSP with inline style allowed for its self-contained layout. Session HTML already had a CSP. Both reports may include private watched paths, so users should treat exported or manually copied report files as sensitive.
