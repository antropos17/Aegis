# Guided Observatory workflows

Open **Start here** from the sidebar. The default launch screen remains
the agent radar. Choose **See running agents**, **Check files before use**, or
**Check an action setup** to open the corresponding workspace. **More you can do**
links the remaining monitoring, investigation, assessment and settings tasks.
Task names also work in **Commands** (`Ctrl K`), with one result per destination.
Distinct workspace icons also identify their task links. Navigation preserves
mounted reviews, drafts and history, and focuses the destination without resetting
its saved scroll.

## Review files

Local security starts with the project scan and **Choose folder and review**.
Expand **Review options** for an inventory, snapshot comparison, external report,
profile layout or offline MCP tools list. The selection summary stays visible
when options are closed. Nothing is executed or uploaded by this review.

A result appears above setup and retains its folder and capture time. Use
**Change review setup** or **View captured result** to move deliberately between
the two. Its suggested action opens and
focuses Findings, Changes or Scope & coverage. All original files, packages,
tool metadata, evidence, export and snapshot operations remain available.
Snapshot acceptance still requires acknowledgment and a fresh matching capture.
No findings or unchanged fingerprints do not establish safety.

## Check an action setup

Choose a single action or catalog and an execution route. The form explains which
JSON files the native dialogs request. Results appear above setup and show a plain-language policy outcome,
the captured selection/time and the next step. Expand **Technical details** for
the full configuration, runtime, terminal and coverage metadata. Catalog decisions
come before technical details. **Change check setup** returns to the existing
draft; receiving a result does not automatically collapse the form or move focus.

Changing the draft does not relabel a previous result. Cancellation and errors
preserve it. These are nonexecuting configuration checks: no authorization is
issued, no client is connected and no blocking test is performed. Process-outage
banners remain on telemetry-dependent pages including Analysis and Reports, while
the independent guide and file/action checks omit them. Global sensor status
is still accessible.

## Choose a project folder

In **Settings → Monitoring → File coverage**, choose one ordinary local project
folder with the desktop folder picker. Selection applies immediately and is
saved separately from public settings. **Refresh folder status** checks the
saved selection; **Clear project folder** removes it. The preview cannot choose
folders. Home roots, system and app-data trees, network paths and linked folders
are refused.

The selection is private to the main process and is absent from settings responses,
configuration import/export and ZIP settings. Normal activity still includes
observed file paths in event details and explicit audit exports. Monitoring uses
the existing depth-five limit and saved exclusions; selecting a folder does not
enable file-read collection or grant permission to read its contents.

The chosen directory works independently of the installation path, including an
ASAR installation. If it disappears or its identity changes, project coverage
becomes unavailable without choosing another root. The existing health poll
checks this transition within its 30-second interval. Choose the folder again to
approve its current identity. Clearing selection restores the existing source
checkout behavior; an ASAR app root remains inapplicable. Use **Monitoring** for
live watcher health rather than interpreting saved selection as active coverage.

Focused fixture and browser checks cover this flow. Physical folder-picker input
and a packaged application remain separate acceptance steps.
## Optional terminal setup

**Connect an agent to selected actions** in Start here explains MCP configuration,
terminal approval and connection-scoped `aegis_route_status`. An action catalog
contains executable actions; the agent catalog contains recognition signatures.
The buttons open fixed repository documentation URLs through the desktop host and
report whether opening succeeded. They do not execute commands or modify settings.
The simulated preview disables these external buttons. Online documentation tracks
the current source version and may differ from an installed build.

The interface supports its existing English and Brazilian Portuguese locales,
four themes and enlarged text. Disclosures use native keyboard behavior; task
navigation and review jumps retain visible focus.
