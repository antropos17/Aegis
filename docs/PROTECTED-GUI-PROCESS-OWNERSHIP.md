# Administrative GUI process ownership

The retained installation association supports explicit `Start-ProtectedInstallationGui`, `Get-ProtectedInstallationGuiState`, and `Stop-ProtectedInstallationGui`. Installation does not start the desktop application. Each installed epoch permits one launch attempt, consumed before native effects. A successful upgrade supplies a new epoch. The administrative association retains the exact process lease after Stop, including its bounded status and retained-data indication.

The selected principal is the original installer's observed linked limited token. With alternate-user UAC this identifies the administrator's linked principal; it does not identify the original desktop requester. Process ownership establishes no GUI enrollment, authenticated renderer route, provider permission, guest readiness, or loaded-code attestation. Returned state keeps `guiEnrollment=false` and `launchAllowed=false`.

Start verifies the original published stage, parent, candidate record, immutable complete bundle and retained principal. A typed transition replaces staging handles with strict read-only execution pins, retaining original volume/128-bit IDs, names, descriptors, metadata, stream and hash expectations. Ancestor protection and exact revalidation cover the bounded descendant handoff; continuous descendant-handle protection is not claimed during that transition. Expected busy checks refuse without poisoning the bundle. The original principal's reentrant lifecycle gate also protects upgrade, uninstall, stage creation/move/removal, ancillary cleanup and principal disposal.

Execution retains both the original by-ID handle and a separately verified named-link handle for every package file and directory. The named handle opens only the expected existing entry, without write or delete sharing, and must match the original identity, name, type, security and metadata. The complete tree and file hashes are checked while both handles are held. A substituted name is refused without adopting or deleting the replacement. Both pins remain held until the original root has exited and the Job is empty; restoration then reopens only the original staging objects. A by-ID read handle alone does not establish the namespace deletion guarantee on the tested host.

Before publication, staging creates or retrieves the optional NTFS shell object ID on its original newly created GUI executable handle, then freezes metadata. This prevents first-window link tracking from changing ChangeTime after execution pins are established. Object IDs are never assigned, replaced or used as ownership authority. Creation failure refuses staging, including on unsupported filesystems; no runtime metadata exemption is added. See the [packaged desktop milestone](development/packaged-desktop-milestone.md) for the native reproduction, actual-package probe and evidence limits.

A fresh profile lives under the native linked-token LocalAppData folder at `AEGIS/ProtectedGui/<install-id>/<random-attempt>`. Namespace effects occur under that limited principal. Newly created directories use atomic native FILE_CREATE and retain the returned original handle. Existing ancestors are pinned against rename/reparse substitution. The original attempt root must initially be empty. Mutable same-principal user data is not package authority or a defense against that principal modifying their own profile. Stop closes the original profile pins and retains all data; no recursive profile deletion exists.

The process starts suspended with fixed profile arguments, exact bundle working directory, no inherited handles and an explicit finite Unicode environment containing only native system paths and original-profile temporary paths. A private kill-on-close Job is assigned atomically through the process attribute list, with a 64-process limit and no breakaway. The original process handles, PID/birth, image, Job and primary-token relation are observed before the sole Resume attempt. The lease is retained in the association before preparation and release. An existing Electron singleton is never adopted.

The fixed 30-minute lease uses Stopwatch and an owned timer. Timer cleanup and administrative operations serialize through the same lifecycle gate. The deadline does not preempt synchronous native calls or abandon mandatory cleanup. Stop targets the original Job even after currentness failure, requiring original-root exit and zero active Job members before restoration. A root exit alone does not establish tree completion. Failed observation, close, or pin restoration retains the original owner and sticky cleanup-unknown state; it does not authorize another attempt or replacement adoption.

The main-process `--aegis-owned-gui-profile` selector configures ordinary storage only. It accepts exactly one existing canonical directory and sets both Electron userData and sessionData before settings, CLI dispatch and single-instance selection. Normal startup without the selector follows the existing path. This flag is not proof of administrative launch or authenticated authority.

Verification distinguishes actual disposable native process/Job/file operations from modeled installation account, service, VM, linked-token and protection authority. Compile-out factories and failure checkpoints do not exist in the production build. A modeled expiry dispatch proves the shared revocation path, not a measured 30-minute wait. Native helper controls do not qualify a real packaged Electron/UAC desktop launch or authenticated UI operations.
